# Design

## Отмена устаревших запросов

`CountrySearchController.setQuery` отменяет текущий `AbortController` сразу при
каждом изменении ввода, до ожидания debounce. Поэтому предыдущий `fetch`
получает отменённый сигнал уже во время задержки перед следующим запросом.
При очистке поля выполняется та же отмена, а debounce сбрасывается пустым
значением, так что запрос не отправляется.

Для запроса объединяются пользовательский сигнал отмены и
`AbortSignal.timeout` через `AbortSignal.any`. В `catch` контроллер различает
`AbortError` и `TimeoutError`: пользовательская отмена не меняет состояние на
ошибочное, а таймаут показывается как ошибка с возможностью повтора.

Отмена нужна не только для экономии запросов. Она останавливает ненужную работу
на стороне сети и не позволяет старому ответу заменить результат нового поиска.
Одного флага актуальности недостаточно: он может скрыть устаревший результат в
интерфейсе, но сам запрос продолжит выполняться. Перед обработкой ответа
контроллер также проверяет, что запрос всё ещё активен; эта проверка дополняет
реальную отмену, но не заменяет её.

## Задержка debounce

Для поиска выбрана задержка **300 мс**. Она даёт пользователю короткую паузу
между вводом символов, чтобы не отправлять запрос на каждую клавишу, но обычно
не заставляет долго ждать после завершения ввода.

Без debounce быстрый набор текста создавал бы много лишних запросов. Слишком
большая задержка уменьшила бы количество запросов, но поиск ощущался бы
медленным, особенно при вводе короткого запроса.

## Сложность преобразования и кэша

`mapCountryResponse` в `src/utils/mapCountryResponse.ts` копирует фиксированное
число полей страны и проходит по массиву языков, создавая новый массив имён.
Если в ответе `n` языков, время работы составляет **O(n)**, а дополнительная
память для массива имён в результате — **O(n)**. Число остальных полей
постоянно и не меняет асимптотическую оценку.

`AsyncRequestCache` в `src/utils/cache.ts` использует `Map` для сохранённых
ответов и запросов в полёте. Поиск по нормализованному запросу и добавление
кэша занимают **O(1) в среднем**. Память составляет **O(S)**, где `S` —
суммарный размер сохранённых ответов и ключей; кэш хранится в памяти и не имеет
ограничения размера или срока жизни. Одновременные запросы с одним ключом
используют один сетевой запрос. Для каждого вызывающего отдельно отслеживается
его сигнал отмены; общий запрос прерывается, когда отменились все ожидающие.

## Принципы чистого кода

- **Разделение ответственности:** `searchCountries` в
  `src/api/searchCountries.ts` отвечает за HTTP-запрос и статусы ответа;
  `mapCountryResponse` в `src/utils/mapCountryResponse.ts` — за преобразование
  данных; `debounce` в `src/utils/debounce.ts` — за задержку вызова. Эти
  функции не зависят от DOM.
- **Отдельная ответственность состояния поиска:** `CountrySearchController` в
  `src/app/CountrySearchController.ts` связывает ввод, debounce, отмену,
  таймаут, кэш и состояния поиска. UI получает состояние через callback и не
  управляет сетевым запросом напрямую.
- **Явные состояния и типы ошибок:** контроллер представляет поиск состояниями
  `idle`, `loading`, `results`, `empty` и `error`, а
  `classifySearchError` в `src/utils/classifySearchError.ts` различает отмену,
  таймаут, HTTP- и сетевую ошибки. Это позволяет интерфейсу показывать
  подходящее сообщение.
- **Типобезопасность и проверка входа:** TypeScript-типы описывают данные и
  состояние поиска, а контроллер проверяет неизвестный ответ API перед
  преобразованием и отображением.
- **Безопасная работа с DOM:** `src/main.ts` создаёт элементы и задаёт динамичный
  текст через DOM API, а не вставляет строки ответа API как HTML.
- **Проверяемость:** чистые функции, кэш и контроллер проверяются тестами без
  реальной сети. В частности, `test/cache.test.ts` проверяет повторное
  использование результата и независимость сигналов отмены совместного
  запроса.
